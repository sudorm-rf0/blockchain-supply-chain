## 3. 链上多签闸门（已实现，2026-08-09）

**准确表述**：已实现**链上多签闸门**（默认关闭，需部署配置 + 正路径验证后方可判定根治）。
本实现不是"出厂即多签"，而是"可开启的链上强制闸门"：

- `trade-finance` / `supply-chain` 的 `PoolState` / `Registry` 新增字段：
  `multisig: Option<Pubkey>` + `multisig_vault_index`（默认 0，可参数化）+
  `pending_multisig` / `pending_multisig_proposed_at` / `pending_multisig_delay_secs` /
  `pending_multisig_vault_index`（两步时锁轮换）。
- 新增指令：`propose_multisig`（当前授权者提案，时锁下限复用治理延迟 >= 86400s）/
  `accept_multisig`（时锁结束后生效）；`new_multisig = Pubkey::default()` 表示清除多签回退单管理员。
- `check_authority` 统一接入全部治理/资金指令（trade-finance 21 处、supply-chain 7 处）：
  - `multisig = Some(ms)`：`admin` 签名者必须 == **Squads vault PDA**
    （`PDA(["multisig", ms, "vault", multisig_vault_index], SQDS4ep65...)`）。
    多签 3/5 执行 VaultTransaction 时，Squads 程序以内层 CPI 用 vault PDA 签名调用本程序；
    单私钥无法伪造该 PDA 签名 → **单签自动失效**。
  - `multisig = None`：回退单管理员直签（向后兼容）。
- **ABI 说明**：`admin: Signer` 保持（无需 `Option<Signer>`/新增账户），仅校验逻辑改为
  vault PDA 比对；`PoolState`/`Registry` 尾部追加字段，indexer parser 已同步
  （`pool-state.parser.ts` size 402→485 + 新字段解析；`layout-anchor.spec.ts` 布局表 + 单测）。
- **回归测试**：trade-finance 7 个 + supply-chain 4 个 H-1 用例（None 回退 / propose /
  时锁未到拒绝 / 时锁后启用 / 单签被拒 / 单签无法发起轮换绕过 / vault PDA 派生一致），
  `anchor test` **82/82 passing**；后端 **156/156**。
- **运维要求（重要）**：多签模式下，所有 admin 调用**必须**走 Squads **VaultTransaction**
  （vault 作为内层 CPI 签名者）；普通 `transactionExecute`（Transaction PDA 签名）会被
  `MultisigEnforced` 拒绝——这是设计使然，防止绕过闸门。金库索引由 `multisig_vault_index`
  指定（默认 0），若多签运营金库索引非 0 须在 `propose_multisig` 显式传入。

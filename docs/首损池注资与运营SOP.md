# 首损池（First-Loss Reserve）注资与运营 SOP

> 版本：v1.0 · 2026-08-07
> 关联：H-04 费率重构方案（docs/H-04-费率重构方案.md）、合约指令 `deposit_first_loss` / `withdraw_first_loss`
> 状态：**草案，待运营/财务确认后生效**

---

## 1. 目的与适用范围

首损池是平台方以自有资金注入的**真实 USDC 损失吸收层**，在违约发生时先于 LP 承担损失（合约 `default_deal` 已实现"先扣首损、后及 LP"）。本 SOP 定义首损池的**注资、对账、补足、提取**全流程，适用于平台运营、财务、风控三线。

---

## 2. 角色与职责

| 角色 | 职责 | 说明 |
|------|------|------|
| **平台财务（注资人）** | 发起并执行 `deposit_first_loss`；持有注资钱包 | 注资钱包为平台自有运营钱包（admin/多签成员） |
| **风控（审批人）** | 审批注资/补足/提取；监控首损池水位 | 根据违约数据提出补足建议 |
| **运营（执行人）** | 调用链上指令；维护对账表；触发告警 | 与 indexer/对账脚本对接 |
| **审计（监督）** | 定期复核首损池余额与消耗 | 独立于运营 |

> 合约层面 `deposit_first_loss`/`withdraw_first_loss` 仅校验 `pool.admin`，**上线后 admin 应为多签**（H-03），所有注资/提取均需多签通过。

## 3. 注资规模

### 3.1 目标规模（推荐）

```
目标首损池 = 在途垫付总额 × 6%
在途垫付总额 = escrow_funded + active_capital（链上 PoolState 字段）
```

| 在途垫付规模 | 目标首损池 |
|--------------|------------|
| 100,000 USDC | 6,000 USDC |
| 1,000,000 USDC | 60,000 USDC |
| 10,000,000 USDC | 600,000 USDC |

### 3.2 规模依据

- 目标违约率 2% × 平台承担 60% = 年化损耗 ≈ 在途的 **1.2%**
- 6% 规模可缓冲约 **5 期**违约周期（给补足留出时间）
- 合约最低保留：`MIN_FIRST_LOSS_ABS = 100 USDC`（仅防清零，运营目标远高于此）

### 3.3 分阶段注资建议

| 阶段 | 在途规模 | 注资节奏 |
|------|----------|----------|
| 灰度期（< 100 万 USDC 在途） | 首批注入 5,000–10,000 USDC | 一次性注入，观察 |
| 成长期（100 万–1,000 万 USDC） | 按在途 6% 动态补足 | 每周对账后补足 |
| 成熟期（> 1,000 万 USDC） | 按在途 6% + 风险缓冲 2% | 每日对账，自动触发补足 |

## 4. 注资流程（deposit_first_loss）

### 4.1 前置条件

- [ ] 资金池已初始化且 `fee_apy_bps` 已按业务决策设置（默认 670）
- [ ] 注资钱包已持有足额 USDC（主网 USDC：`EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v`）
- [ ] 风控审批通过（首损池注资申请单）

### 4.2 操作步骤

1. 财务钱包向自身 USDC ATA 转账（如需要）
2. 调用 `deposit_first_loss(amount)`：
   - 账户：`pool_state`、`admin`（注资钱包，Signer）、`depositor_token_account`、`pool_authority`、`pool_token_account`、`usdc_mint`、`token_program`
3. 交易确认后核对：
   - `PoolState.first_loss_reserve` 增加 amount
   - `total_assets`、`nav` **不变**（首损不计 LP 净值，属预期）
   - 金库现金增加 amount
4. 记录注资台账（见第 6 节）

### 4.3 注意事项

- 首损注入**不改变** LP 净值（合约 `equity_base` 剔除首损），勿误判为"资金池变大了"
- 首损资金在 pool vault 内，但**不可被 LP 赎回**（`redeem_lp` 有 `vault_after >= first_loss_reserve` 保护）

## 5. 违约消耗与补足规则

### 5.1 消耗机制（合约已实现）

还款期违约（REPAYING）时：

```
应收 P 核销 → 保险基金账面赔付（P×10%）→ 剩余损失 min(剩余, first_loss_reserve) 由首损承担
→ LP 承担最终剩余
```

- 首损按"耗尽式"覆盖（首损池有多少承担多少），无固定比例参数
- 实际分担比例 = 首损池余额 / 违约损失，随池子水位动态变化

### 5.2 补足触发

| 触发条件 | 动作 | 时限 |
|----------|------|------|
| 首损池 < 目标规模的 50% | 风控发起补足申请 | 3 个工作日 |
| 首损池 < 目标规模的 30% | **紧急补足**（先补至 100% 再补 6% 缺口） | 1 个工作日 |
| 单笔违约消耗 > 首损池 20% | 风控复盘该笔违约 | 立即 |
| 连续 3 笔违约 | 暂停新放款（建议暂停 fund_deal）并全面复核 | 立即 |

### 5.3 补足公式

```
补足金额 = max(0, 目标首损池 - 当前首损池)
目标首损池 = (escrow_funded + active_capital) × 6%
```

## 6. 对账机制

### 6.1 对账频率与责任

| 频率 | 内容 | 责任人 | 依据 |
|------|------|--------|------|
| 每日 | 首损池余额快照（链上 `first_loss_reserve`） | 运营 | indexer pool snapshot / `get_pool_info` |
| 每日 | 违约事件统计（`DefaultEvent` 数量与首损消耗） | 运营 | 链上事件订阅 |
| 每周 | 首损池 vs 在途垫付比例核算 | 风控 | 对账表 |
| 每月 | 首损池注资/消耗/提取全量复核 | 审计 | 链上 + 财务凭证 |

### 6.2 对账公式（链上校验）

```
一致性校验：
  PoolState.first_loss_reserve
    = 累计 deposit_first_loss - 累计 default 首损消耗 - 累计 withdraw_first_loss
  （链上 event 可导出前三者，独立复核）

水位校验：
  首损覆盖率 = first_loss_reserve / (escrow_funded + active_capital)
  目标 ≥ 6%，预警 < 3%，紧急 < 1.8%
```

### 6.3 对账工具

- indexer 已解析 `firstLossReserve` / `escrowFunded` / `activeCapital`（新布局 297 字节）
- 对账脚本可复用 `scripts/reconcile.mjs` 扩展首损字段

## 7. 提取规则（withdraw_first_loss）

| 规则 | 说明 |
|------|------|
| 审批 | 需风控 + 财务双签（多签治理） |
| 最低保留 | 提取后 `first_loss_reserve ≥ 100 USDC`（合约）且 ≥ 目标规模的 50%（运营更严） |
| 提取上限 | 仅允许提取**超出目标规模**的部分 |
| 例外 | 平台终止运营/清盘时，经治理决议可全量提取 |

## 8. 监控与告警

| 监控项 | 阈值 | 告警通道 |
|--------|------|----------|
| 首损覆盖率 | < 3% | 风控 Webhook + 邮件 |
| 首损池绝对值 | < 目标 50% | 运营群 |
| 单笔违约消耗 | > 首损池 20% | 风控即时 |
| 违约率（滚动 30 天） | > 目标违约率（默认 2%） | 风控 + 业务 |
| withdraw_first_loss | 任何非计划提取 | 审计 |

---

## 9. 应急流程（首损池耗尽）

1. **立即**：暂停新放款（`set_paused(true)` 或风控审批暂停 fund_deal）
2. **12 小时内**：财务紧急补足至目标规模
3. **48 小时内**：风控出具违约归因报告（是否系统性风险 / 欺诈 / 模型失效）
4. **恢复条件**：首损池 ≥ 目标规模 + 违约率回归目标内 + 治理决议
5. 若持续违约超目标：按 H-04 决策 D2 重新校准 `fee_apy_bps`（`set_fee_params` + 时锁）

# 可复现构建与链上字节码验证

> 目的：证明"链上部署的字节码来自被审计源码"（DFR-2026-0148 建议项）
> 核心：固定工具链 + 锁定 Cargo.lock → 同源码两次构建哈希一致 → 与链上字节码比对

---

## 1. 可复现构建（本地/CI）

```bash
# 构建一次，输出 .so SHA-256 + 工具链快照
bash scripts/reproducible-build.sh

# 构建两次比对哈希（确定性证明）
bash scripts/reproducible-build.sh --verify-twice
```

**结果示例**：
```
trade_finance: d88ca506ed2a2899...
supply_chain:  ac24f0e7e7598f92...
deterministic: yes (two builds identical)
```

可复现性依据：
- `packages/contracts/Cargo.lock` 已锁定（SHA-256 记录在报告）
- Anchor 0.31.1 / Solana 4.1.2 (SBFv3) / Rust 固定
- CI contracts job 已集成 `--verify-twice`（每次 push 自动验证确定性）

## 2. 链上字节码对比

```bash
# 对比 devnet（默认）
bash scripts/verify-reproducible.sh

# 对比主网
SOLANA_RPC_URL=https://api.mainnet-beta.solana.com \
  TRADE_FINANCE_PROGRAM_ID=<新ID> SUPPLY_CHAIN_PROGRAM_ID=<新ID> \
  bash scripts/verify-reproducible.sh
```

原理：`solana program dump <PID>` 下载链上字节码 → SHA-256 与本地 `.so` 比对。
- **PASS**：链上字节码 = 本地可复现构建（被审计源码）
- **FAIL**：链上未部署最新版（如 devnet 旧部署）或字节码被篡改

## 3. 主网上线使用

1. `bash scripts/reproducible-build.sh` 生成最新 `.so` 与哈希（记录到 release 说明）
2. `deploy-mainnet.sh` 部署
3. `bash scripts/verify-reproducible.sh`（主网 RPC + 新 Program ID）→ **PASS**
4. 将两份哈希（trade/supply）+ 工具链快照附到上线记录，供第三方独立复核

## 4. solana-verify（官方替代，可选）

若需更强的第三方独立验证，可安装官方 `solana-verify`（Ellipsis Labs）：
```bash
# 安装（crates.io 包名以官方 README 为准）
cargo install solana-verify-cli
# 在固定 Docker 镜像中构建并校验
solana-verify build
solana-verify verify <PROGRAM_ID> --url <RPC>
```
本仓库的 `reproducible-build.sh` 已实现等价的核心证明（两次构建一致 + 链上对比），不依赖外部镜像/CLI；如需官方工具链背书再引入 solana-verify。
